# 01.05 — Airbyte: Specification

Status: Implemented
Phase: [01 — Ingestion: Airbyte Writing Parquet to S3](../plan.md)

## Design

Two manifests in `platform/aws`, synced by the root Application `platform` (01.04); they reach the
cluster after `git push` to `main`.

| Item | Value | Why |
|---|---|---|
| StorageClass | `auto-ebs-sc`: `provisioner: ebs.csi.eks.amazonaws.com`, `type: gp3`, `encrypted: "true"`, `volumeBindingMode: WaitForFirstConsumer`, `allowedTopologies` on `eks.amazonaws.com/compute-type: auto`, annotated `is-default-class: "true"` | Auto Mode creates no StorageClass ([D-006](../../../docs/decisions/006-eks-compute-mode.md)); the AWS example as is. Default because the chart's Postgres PVC sets no `storageClassName`. Encrypted with the `aws/ebs` key |
| Application | `airbyte` in `argocd`: chart `airbyte` **2.4.0** from `https://airbytehq.github.io/charts` (chart v2, app 2.4.0), values in `helm.valuesObject`, destination namespace `airbyte` (`CreateNamespace=true`), finalizer `resources-finalizer.argocd.argoproj.io` | Values in the same file (single source). Release name `airbyte`, so the Service is `airbyte-airbyte-server-svc:8001` |
| Sync | `automated: { prune: true }`, **without `selfHeal`** ([D-019](../../../docs/decisions/019-airbyte-sync-policy.md)) | Chart hooks are recreated on every sync |
| Storage | `global.storage.type: s3`; the 5 bucket keys (`log`, `state`, `workloadOutput`, `activityPayload`, `auditLogging`) = `eks-for-data-airbyte-<account_id>`; `s3.region: us-east-1`; `s3.authenticationType: instanceProfile`; `minio.enabled: false` ([D-009](../../../docs/decisions/009-airbyte-internal-storage.md)) | `instanceProfile` uses the AWS SDK default credential chain, and so IRSA |
| IRSA | `serviceAccount.annotations: eks.amazonaws.com/role-arn: arn:aws:iam::<account_id>:role/eks-for-data-airbyte` ([D-008](../../../docs/decisions/008-pod-aws-identity.md), [D-020](../../../docs/decisions/020-aws-account-id-in-git.md)) | ServiceAccount `airbyte-admin` (chart default), used by all pods, sync jobs included. Values from the `infra/aws/cluster` outputs |
| Database | Bundled Postgres (`airbyte-db`, PVC 500Mi, rounded up to the 1 GiB EBS minimum) ([D-009](../../../docs/decisions/009-airbyte-internal-storage.md)) | The chart's default credentials are reachable only inside the cluster (ClusterIP); nothing added to the repository |
| Login | `global.airbyteUrl: http://localhost:8001`; auth on (chart default): email given at first access, password generated by Airbyte in the `airbyte-auth-secrets` Secret | No password in the repository |
| Resources | Requests, no limits: `server` and `worker` 500m/1Gi; `workloadLauncher` and `workloadApiServer` 250m/768Mi; `manifestServer` 250m/512Mi; `cron` 100m/512Mi; `temporal` 250m/256Mi ([D-018 update](../../../docs/decisions/018-workload-resource-requests.md#update--2026-10-23-airbyte-needs-requests-to-start)); usage measured in check 9 | Without requests Airbyte does not start (CPU starvation on one node); with them Auto Mode sizes the nodes. Final values and memory limits set from measured data |

**S3 storage writes** (logs and state) only happen with jobs; they are proven in 01.06 by the first
connector check and sync. Here, check 6 proves that IRSA reached the pods.

**Prerequisite:** 01.03 and 01.04 implemented.

**Cost:** one gp3 EBS volume of 1 GiB (about US$ 0.08/month) plus the nodes Auto Mode creates for
Airbyte, which is much larger than Argo CD: its requests (2100m CPU, about 4.8Gi) take about 4 vCPU
of nodes in total (e.g., 2 × `c6a.large` or one `c6a.xlarge`/`m6a.xlarge`, US$ 0.15–0.17/h), chosen
by Auto Mode.

## Teardown

```bash
set -a; source .env; set +a
kubectl delete application platform -n argocd   # cascades to airbyte
kubectl delete namespace airbyte                # PVC (not deleted by the cascade) → EBS volume deleted
terraform -chdir=infra/aws/gitops destroy
```

Then `infra/aws/cluster` is destroyed. The namespace must go **while the cluster is up**, so the EBS
CSI deletes the volume; otherwise it is left behind and keeps costing.
