# D-048 — Spark Job Code Delivery

Status: Accepted
Date: 2026-11-02
Phase: specs/03-processing-spark-iceberg

## Context

A job's PySpark script lives in `pipelines/spark/` (README §6), and the driver pod needs it at start.
With the custom image of [D-047](047-spark-dependencies.md), baking the script into the image is also
possible.

## Alternatives

| Alternative | Best Practices | Simplicity | Cost | Consistency with the Whole |
|---|---|---|---|---|
| A. ConfigMap generated by Argo CD (Kustomize) from `pipelines/spark/*.py`, mounted in the driver | GitOps: a push updates the job in seconds | One Kustomize entry, no build | None | Code (`pipelines/`) apart from the image (platform), README §6; limit 1 MiB per ConfigMap |
| B. Script uploaded to S3, referenced as `s3a://` | Common on EMR; code in S3 can drift from Git | An upload step and its permissions | Negligible | A bucket per cloud |
| C. Script copied into the `ghcr.io` image | Code and dependencies versioned together | Every code change triggers an image build (minutes) | None | Mixes pipeline code into the platform image |

## Decision

- **Recommended:** A, because it is GitOps, the fastest from edit to run, and keeps code apart from
  the image.
- **Chosen:** A
- **Reason:** follows the recommendation.
