# Project Principles

These principles guide every decision in this project, from planning to implementation.
Principles 1 to 3 are the decision criteria, listed in priority order: when they conflict,
the higher one wins.

## 1. Market Best Practices

Always adopt market best practices. Following proven practices reduces project and implementation risk.
It comes first because the goal of this project is to learn what the best practice is.

## 2. Simplicity

The adopted solution must be simple enough for a layperson to read and understand the project.
Keep the code lean and the number of files small.

## 3. Cost

Always minimize cost, so the project stays economically viable.
It comes last because environments are created and destroyed shortly after use,
so the cost impact is usually small.

## 4. Verify Before Proposing

Before proposing a solution, verify it using the available MCP servers, skills and the internet,
preferring official sources.

## 5. Evaluate Alternatives

Always compare the alternatives in a table, stating precisely and objectively the advantages
and disadvantages of adopting each one against principles 1 to 3.
Alternatives that break principle 7 are discarded before the comparison.

## 6. Recommend a Solution

Always indicate one recommended alternative, chosen by applying principles 1 to 3 in priority order.

## 7. Consistency with the Whole

Every step must stay consistent with the project as a whole: the objective and architecture
in the README, these principles and the decisions already recorded.
When a step needs to diverge, update the affected documents in the same change,
so that the documentation always matches what is implemented.
